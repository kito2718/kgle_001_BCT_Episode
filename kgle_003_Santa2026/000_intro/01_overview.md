# 01. Overview (大会概要)

Kaggle公式ページ: [Santa 2026 - The Elf Calculator (Overview)](https://www.kaggle.com/competitions/santa-2026/overview)

---

## 1. Abstract (要約)

サンタの工房の計算機に問題が発生しました。各おもちゃ製造ステーションは正確な数値リストを生成する必要がありますが、エルフの計算機(Elf Calculator)は一度に48個の値しか保存できません。各命令は、格納されている2つの値を加算、減算、乗算、または正確に除算し、1つのメモリスロット(レジスタ)の値を置き換えます。

あなたの課題は、基本算術演算だけを使用して、与えられた小さな初期値から各パズルのすべての目標数値を生成する最短プログラムを作成することです。

## 2. Description (詳細・背景ストーリー)

### クリスマスキャロル
> _工房の計算機がクリスマスの寒さに凍りついた！_<br>
> _エルフたちが生み出すべき巨大な目標数値が山積みに！_<br>
> _彼らの手元には小さな初期値の種(シード)しかなく、_<br>
> _ソリの指令台には4つのシンプルな記号があるだけ。_<br><br>
> _注意深く、足し、引き、割り、あるいは掛けて、_<br>
> _賢い手順で節約しながら、新たな計算結果を保存せよ！_<br>
> _質素な「3」から、合計が膨らんでいくのを見届けよ、_<br>
> _すべての目標をきちんとした列へと組み立てていく。_<br><br>
> _余計な手順が1つ増えるたびに、ソリの上昇は遅れてしまう、_<br>
> _だからこそ、すべての計算を短く、無駄なく行おう。_<br>
> _プログラムを簡潔に保ち、あなたの論理を輝かせ、_<br>
> _サンタがクリスマスの時間に遅れず飛び立てるよう助けよう！_

### 課題 (The Challenge)
ホリデーラッシュがピークを迎えたまさにその時、北極のおもちゃ計数計算機が基本モード(Basic Mode)でスタックしてしまいました！この計算機は一度に1つの単純な算術演算しか実行できず、余計なステップが1つ増えるたびに組み立てライン全体が遅延してしまいます。
本コンペティションでは、基本算術演算(`+`, `-`, `*`, `/`)を用いて、小さな初期値から特定の大きな目標数値を生成するプログラムを、できる限り少ない合計命令数で作成します。

### 目標 (The Goal)
あなたのスコアは、全1,000問のパズルにわたってプログラムが使用する**算術ステップの総数**です。命令を削ぎ落とすたびに、リーダーボードの上位へと駆け上がることができます。最も短く最も効率的な解法を作り上げたチームがルドルフの心をつかみ、賞金プールを手にします。

4つの基本演算だけでどこまで行けるでしょうか？アルゴリズムを研ぎ澄まし、すべての余計な手順を削ぎ落とし、サンタの工房が時間通りに稼働できるよう支援しましょう！

## 3. Evaluation (評価方法)

### スコアリング
提出物は、**1,000問の採点対象パズル(scored puzzles)** のそれぞれについて算術プログラムを再生(シミュレーション実行)することによって評価されます。
スコアは全1,000プログラムの**命令ステップ数の総和**です。**値が小さいほど優れています(Lower is better)**。

$$\text{Score} = \sum_{p=1}^{1000} |\text{program}_p|$$

- **パブリック/プライベートのリーダーボード分割はありません**。公開リーダーボードのスコアがそのまま全パズルの最終評価となります。
- 同じレジスタを2回読み出す命令、すでに計算済みの値を再度計算する命令、全ターゲットを生成し終えた後に実行される命令を含め、**すべての命令が1ステップとしてカウントされます**。
- すべての命令は合法でなければなりません。**部分点はありません**。
- 各プログラムは[Dataページ(02_data.md)](./02_data.md)に記載された計算機ルールに従い、すべての目標数値を少なくとも1回生成しなければなりません。**いずれか1つのプログラムでも無効であれば、提出全体がリジェクト(無効判定)されます**。

### 提出フォーマット (Submission Format)
提出ファイルは、`id` と `program` の2つのカラムをこの順序で含むUTF-8形式のCSVファイルです。`scored_0001` から `scored_1000` までのすべてのIDが正確に1回ずつ含まれている必要があります。行の順序はスコアに影響しません。

各 `program` セルには、命令のJSON配列が格納されます。各命令は4つの要素からなる配列です:

```json
["+", 0, 1, 2]
```

この例では、レジスタ0とレジスタ1の値を加算し、その結果をレジスタ2に書き込みます。

- 演算子は `"+"`、`"-"`、`"*"`、`"/"` のいずれかでなければなりません。
- 続く2つの要素は、ソースレジスタのインデックスを表す整数(0から47まで)です。両方のレジスタに定義済みの値が入っている必要があります。
- 最後の要素は、書き込み先(デスティネーション)レジスタのインデックスを表す整数(0から47まで)です。
- 書き込みが行われる前に、両方のソース値が読み込まれます。したがって、書き込み先レジスタはソースレジスタと同じであってもよく、両方のソースレジスタが同一であっても構いません(例: `["+", 0, 0, 0]`で2倍する)。

#### CSV出力例:
```csv
id,program
scored_0001,"[[""/"",0,0,1],[""-"",0,1,2],[""+"",0,2,3],[""+"",0,3,4]]"
```
※JSONセル内のダブルクォーテーションは適切にエスケープ(CSV形式で `""` と表現)する必要があります。

### プログラム制限値 (Program Limits)

| パラメータ | 制限値 |
|---|---:|
| パズルあたりのレジスタ数 | 48個(0から47までインデックス) |
| プログラムあたりの最大命令数 | 4,096命令 |
| `program` セルあたりのUTF-8バイト数上限 | 131,072バイト(128 KiB) |
| 任意のレジスタが保持できる値の範囲 | 正の整数であり、かつそのパズルの `value_limit` 以下 |

- すべてのパズルの `value_limit` は $10^{18}$ 以下です。
- サンプル提出(`sample_submission.csv`)では、1パズルあたり最大2,873命令を使用しています。
