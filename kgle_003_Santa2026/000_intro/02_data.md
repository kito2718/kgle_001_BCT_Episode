## 1. 収録ファイル (Files)

### `puzzles.csv`
採点対象となる1,000問のパズルが含まれています。各行が1つの独立したパズルです。

| カラム名 | 型 | 説明 |
|---|---|---|
| `id` | 文字列 | パズルの一意識別子。`scored_0001` から `scored_1000` まで。 |
| `starting_values` | JSON配列 | 開始時に与えられる正の整数の配列。開始時点でレジスタ `0` から `len(starting_values) - 1` に順番に格納されます。 |
| `targets` | JSON配列 | プログラムが少なくとも1回生成しなければならない正の整数の配列(昇順ソート)。 |
| `value_limit` | 整数 | 実行中に任意のレジスタで許容される最大値。$1$ から $10^{18}$ までの整数。 |
| `registers` | 整数 | 利用可能なレジスタの総数。すべてのパズルで常に `48` です。 |

### `practice_puzzles.csv`
採点対象外(練習用)の200問のパズルが含まれています。IDは `practice_0001` から `practice_0200` です。`puzzles.csv` の5つのカラムに加え、以下の情報が付与されています。

| 追加カラム名 | 型 | 説明 |
|---|---|---|
| `family` | 文字列 | 生成ジェネレータのファミリー分類(`independent`, `shared`, `multiplicative`, `mixed`, `tiny`)。 |
| `design_tier` | 文字列 | 難易度ティア(`hard`, `medium`, `easy`)。 |
| `lower_bound` | 整数 | `starting_values` にまだ含まれていない目標の数(`len(set(targets) - set(starting_values))`)。1つの命令は最大で1つの新しい目標しか生成できないため、これは命令数の自明な理論的下限(Lower Bound)となります(通常は緩い下限であり、達成可能とは限りません)。 |

※練習用セットは採点用セットと同じパズルファミリーと算術ルールを使用していますが、デバッグ用に `tiny` パズルの割合が多くなっています。ファミリーの比率は採点用セットとは異なります。

### `sample_submission.csv`
全1,000問のパズルに対する合法なベースラインプログラムが含まれています(合計ステップ数: 1,490,379)。

## 2. エルフの計算機ハードウェア仕様 (Calculator Rules)

各パズルには、`0` から `47` までインデックス付けされた **48個のレジスタ** が存在します。
開始時、`starting_values` の値がそのリスト順に先頭のレジスタ(0, 1, ...)を占有します。その他のレジスタはすべて **未定義(undefined)** です。

命令 `["op", i, j, d]` は、ソースレジスタ `i` と `j` を読み込み、演算子を適用し、その結果を書き込み先レジスタ `d` に書き込みます。
レジスタへの書き込みは、以前の値を上書きします。**両方のオペランドは書き込みが行われる前に読み出されるため、書き込み先はソースレジスタのいずれかと同じであっても構いません**。

### 厳格な5つの計算ルール

1. **値は必ず正の整数(Positive Integers)でなければならない**
   - すべての中間値および最終結果は、厳格に $\ge 1$ の整数でなければなりません。
   - 減算(`-`)は、**第1オペランドが第2オペランドより厳密に大きい場合のみ合法**です($a - b > 0$)。結果が $0$ や負数になる減算は即座に失格となります。
2. **除算は割り切れなければならない(Exact Division)**
   - 第2オペランドは第1オペランドを余りなく割り切る必要があります($a \pmod b == 0$)。
   - 小数点以下や余りが出る除算は違法です。ゼロ除算($b = 0$)も当然違法です。
3. **すべての計算結果は `value_limit` 以下でなければならない**
   - これには**すべての中間値**が含まれます。たとえ後続の命令ですぐに値を小さくするとしても、一時的であれ `value_limit` を超える値を作った時点で違法となります。
4. **ソースレジスタは定義済みでなければならない**
   - 未定義のレジスタから値を読み出すことはできません。未定義のレジスタは、命令によって結果が書き込まれた後に定義済みとなります。
5. **目標(ターゲット)は一度出現すればよい**
   - ある目標値が任意のレジスタに一度でも出現すれば、その目標は達成(Covered)とみなされます。これには開始時の初期値(`starting_values`)に含まれている場合も含まれます。
   - その後、そのレジスタが別の値で上書きされても、達成状態は維持されます。

### 特筆すべき演算テクニック
- **同一ソースの再利用**:
  - `["+", 3, 3, 7]`: レジスタ3の値を2倍してレジスタ7に格納。
  - `["*", 2, 2, 5]`: レジスタ2の値を2乗してレジスタ5に格納。
  - `["/", 0, 0, 4]`: 任意の正の整数をそれ自身で割ることで、**「1」という万能な定数を1ステップで生成**可能。
- **インプレース更新(In-place modification)**:
  - `["+", 0, 1, 0]`: レジスタ0にレジスタ1の値を加算し、レジスタ0自身を上書き。
- **初期レジスタの上書き**:
  - `starting_values` が入っていたレジスタ(0, 1, ...)も、不要になれば自由に上書き可能です。
- **全命令のカウント**:
  - 最後の目標値を達成した後に実行された余分な命令も、すべてスコア(コスト)としてカウントされます。目標を達成したら即座にプログラムを終了させる必要があります。

## 3. 具体例 (Worked Example)

データページに記載されているトイパズルの例です(採点対象ではありません)。

```csv
id,starting_values,targets,value_limit,registers
example_0001,[3],"[1, 2, 5, 8]",9,48
```

- 初期値: レジスタ0に `3`
- 目標値: `1, 2, 5, 8`
- 上限値: `9`
- レジスタ数: `48`

以下のプログラムは、4つの命令ですべての目標をカバーします:

```json
[["/", 0, 0, 1], ["-", 0, 1, 2], ["+", 0, 2, 3], ["+", 0, 3, 4]]
```

### ステップ実行トレース

| ステップ | 命令 | 計算内容 | 書き込み先 | 達成された目標 |
|---:|---|---|---|---|
| 開始 | - | 初期状態 | Reg 0 = 3 | (なし) |
| 1 | `["/", 0, 0, 1]` | $3 \div 3 = 1$ | Reg 1 = 1 | `1` |
| 2 | `["-", 0, 1, 2]` | $3 - 1 = 2$ | Reg 2 = 2 | `1, 2` |
| 3 | `["+", 0, 2, 3]` | $3 + 2 = 5$ | Reg 3 = 5 | `1, 2, 5` |
| 4 | `["+", 0, 3, 4]` | $3 + 5 = 8$ | Reg 4 = 8 | `1, 2, 5, 8` (全達成!) |

## 4. データセットの統計・性質 (EDA分析)

採点対象の1,000問(`puzzles.csv`)を分析した基本統計です:

- **パズル総数**: 1,000問
- **1問あたりのターゲット数**: 平均 26.9個 (最小1個 〜 最大32個、中央値30個)
- **1問あたりの初期値数**: 平均 3.5個 (最小1個 〜 最大8個、中央値3個)
- **ターゲット値のサイズ**: 数十〜最大約 $10^{18}$ (約60ビット)
- **パズルファミリー分類**:
  1. `Independent` (約215問): 完全にランダムに近い大きな数値。
  2. `Shared` (約264問): 共通の隠れたハブ(共通因数/ベース値)の倍数＋小さなオフセット。
  3. `Multiplicative` (約189問): シード値の積＋オフセット構造。
  4. `Mixed` (約182問): 構造化された部分とランダムな部分の混合。
  5. `Medium` (約134問): 約25ビット前後の比較的小さなターゲット群。
  6. `Tiny` (約16問): 最短手数が極めて短い自明なパズル。
